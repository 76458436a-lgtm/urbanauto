# Urban Auto Exp 54 [EXP] 5.4.0-exp6

Результаты проверок и границы применимости приведены в [VALIDATION.md](VALIDATION.md).

Экспериментальный модуль QGIS для выделения **территории городской застройки** по подготовленным спектральным индексам и анализа её динамики. Это обобщённые территории, а не контуры отдельных зданий. Пороговая классификация может путать открытый грунт и застройку; автоматизация не заменяет независимую проверку.

## Установка

QGIS 3.34 и новее: **Модули → Управление модулями → Установить из ZIP**. Выберите ZIP, затем включите Urban Auto Exp 54 [EXP]. Если модуль уже загружен, после обновления перезапустите QGIS. Встроенные библиотеки QGIS: GDAL/OGR, NumPy; для фильтрации временного ряда нужна SciPy. Сетевые границы OSM опциональны.

## Новое в 5.2: точки пользователя и точность в отчёте

- **Точки проверки → точность в отчёте.** Инструмент «Точки для разметки» в режиме «для проверки точности» выбирает
  точки случайно, поровну в застройке и вне её. Разметьте поле label (1 – застройка, 0 – нет) и передайте слой в
  расчёт параметром «Точки проверки»: в обучение они не входят, а `report.html` покажет каппу, общую точность и
  площадь застройки по точкам с 95 % доверительным интервалом (метод Olofsson et al., 2014). Это честная оценка
  точности конкретной карты, которую можно показывать заказчику.
- **Точки для обучения.** Режим «для обучения» выбирает места, где модель сомневается; размеченные точки добавляются
  в расчёт параметром «Точки пользователя».
- **Порог по точкам** (`calibrate=True` в Python API) – экспериментально, по умолчанию выключен.

Проверка на 10 малых городах (Нерехта, Кондопога, Бирск, Ялуторовск, Белогорск, Вязьма, Котлас, Чистополь, Ишим,
Дальнереченск): по 40 точек «где модель сомневается», размечены по снимкам; точность – на 800 независимых точках,
не входивших в обучение. Средняя κ 2025 г.: без точек 0,776, с точками 0,798, с точками и порогом 0,782. Сильнее
всего точки помогли Ялуторовску (0,74 → 0,84), Вязьме (0,62 → 0,69), Нерехте и Дальнереченску; в Белогорске
ухудшили (0,71 → 0,66). Вывод: 40 точек дают небольшой прирост, но не выводят все малые города на κ 0,9; главная
ценность разметки – измеренная точность карты в отчёте.

## Новое в 5.1: определение застройки

Проверка 5.0 показала, что в малых городах с частным сектором карта завышает площадь в 1,2–2,7 раза: в застройку
попадали огороды, деревья и газоны у домов. Причина – обучающие метки: GHSL (90 м) «размазывает» застройку, а контуры
зданий OSM отмечали каждый пиксель, который здание задевает краем.

Теперь есть параметр **«Определение застройки»**:
- **строгое** (по умолчанию) – здания, дворы, промплощадки и покрытия. Контуры зданий OSM и Microsoft считаются как
  доля площади пикселя (≥ 8 %); зелень в посёлке (GHSL > 0, но ESA/WSF 10 м и контуры зданий застройки не видят)
  учится как растительность; метка застройки любого года подтверждается резкими продуктами 2019–2021 гг.;
- **территория** – кварталы целиком, вместе с дворами и зеленью, как в 5.0 и в ВКР по Ураю.

Выбор по 11 размеченным городам (Урай + 5 городов 4.4 + 5 малых городов 5.0), κ 2025 г. в среднем: 5.0 – 0,75,
строгое – 0,78; малые города 0,67 → 0,76, Ханты-Мансийск 0,78 → 0,91 (площадь +36 % → +5 %), Кондопога
0,62 → 0,74, Белогорск 0,47 → 0,71. На Урае, где эталон размечен как «территория», строгий режим хуже
(0,97 → 0,84): для сопоставления с ВКР используйте режим «территория».

**Отложенная проверка** на пяти новых случайных городах (Вязьма, Котлас, Чистополь, Ишим, Дальнереченск; 400 точек,
настройки зафиксированы заранее): средняя κ 2025 г. – 0,75 («территория») → **0,83** (строгое); завышение площади
1,35–1,56 → 1,07–1,19 раза.

## Новое в 5.0

**Запуск по названию города.** В инструменте «Годовой ряд застройки» можно не рисовать полигон, а ввести
название («Нерехта», «Белогорск, Амурская область»). Центр находит геокодер OSM (Nominatim), а охват –
по фактической застройке GHSL вокруг него с буфером 1,5 км.

**Точнее год появления застройки.**
- Модель – градиентный бустинг (HistGradientBoosting) вместо Random Forest; при его отсутствии в scikit-learn
  модуль сам возвращается к Random Forest.
- Новые признаки: сходство пикселя с его же состоянием в последние годы (дом, стоявший в 2000 г., похож на себя
  в 2025 г.), текстура и плотность границ в окнах 90 и 270 м.
- Год появления ищется с весом наблюдений: композит из одной-двух сцен весит меньше, чем из шести.
- Проверка на 6 городах (Урай 220 точек × 6 лет, ещё 5 городов по 90 точек): относительно 4.5 исправлено
  63 точки, испорчено 24 – почти всё за счёт года появления на Урае: κ 2000 г. – 0,77 → 0,82,
  2015 г. – 0,84 → 0,97, 2025 г. – 0,94 → 0,97. Карта 2025 г. в остальных городах – в пределах шума (±0,05).

**Отложенная проверка на 5 новых малых городах** (Нерехта, Кондопога, Бирск, Ялуторовск, Белогорск – выбраны
случайно, по одному на крупный регион; 400 точек; параметры зафиксированы до проверки): средняя κ 2025 г.
4.5 – 0,68, 5.0 – 0,67, то есть точность карты последнего года не изменилась. Обе версии в малых городах с
частным сектором завышают площадь в 1,2–2,7 раза: в застройку попадают огороды, деревья и газоны рядом с домами;
слой новой застройки там верен примерно в трети случаев. Для малых городов результат нужно проверять по точкам
(инструмент «Точки для разметки» + точки пользователя) – см. TESTING.md.

**Новые результаты.**
- `Built_fraction_by_year.tif` – доля застроенной поверхности в пикселе по годам (регрессия по ESA WorldCover и
  WSF 2019 10 м); в `annual_series.csv` – столбец `built_surface_km2`.
- `New_built_<годы>.gpkg` – пятна новой застройки с полями год, площадь (га), средняя уверенность, число пикселей.
- `report.html` – отчёт одним файлом: площадь и прирост по годам (диаграмма), таблица, источники, модели.

**Точки пользователя (активное обучение).** Инструмент «Точки для разметки» выбирает по готовому результату
места, где модель сомневается. Пользователь отмечает их по снимку (поле label: 1/0) и запускает расчёт заново
с этим слоем – точки входят в обучение с весом 20.

**Метки.** Добавлены контуры зданий Microsoft Global ML Building Footprints (там, где они есть: для Урая и
Сургута квадратов нет). На шести городах они не изменили точность, но страхуют от сбоя или пустоты OSM.

**Sentinel-2 (необязательно).** Признаки 10 м внутри пикселя 30 м за 2018 г. и позже (средние индексы, их разброс,
доля «непроницаемых» и «зелёных» подпикселей). На шести городах выигрыша не дали (+62/−25 против +63/−24 без них)
и добавляют около 5 минут загрузки на город, поэтому по умолчанию выключены.

**Скорость.** Статистики ряда считаются одной сортировкой (в ~40 раз быстрее `nanpercentile`), годы
прогнозируются параллельно, слой новой застройки строится за один проход на год. Пять малых городов
(26 лет, кэш снимков): 4.5 – 64–276 с на город, 5.0 – 30–59 с.

## Новое в 4.5

Годовой ряд RF проверен на шести городах по 670 независимым точкам. Что изменилось:
- дороги и ж/д OSM, рядом с которыми нет зданий, не попадают в обучающие метки застройки и учатся как «не застройка»;
- в метки «открытый грунт» не попадают пиксели со зданиями OSM, а при расчёте года появления вероятность «грунта»
  под зданием OSM добавляется к вероятности застройки (светлые плоские крыши складов похожи на песок);
- новая застройка признаётся, если её подтверждают ≥ 3 года (было 2);
- тонкие отростки новой застройки шириной 1–2 пикселя снимаются морфологическим открытием 3 × 3.

Проверенные и отклонённые варианты: фильтр «дорога без здания» на итоговой карте и порог средней вероятности 0,6
снимали настоящий прирост на Урае и в Калуге – в коде оставлены как необязательные параметры, по умолчанию выключены.

## Новое в 4.4: годовой ряд застройки без ручных точек

Меню «Городской анализ → Годовой ряд застройки (Random Forest, без точек)» или алгоритм Processing
`urban_auto_exp54:rf_series`. Нужны только полигон территории, годы и интернет.

1. **Снимки за каждый год.** Модуль сам ищет сцены Landsat 5/7/8/9 Collection 2 Level-2 в Microsoft
   Planetary Computer за лето (июнь–август), убирает облака, тени и снег по маске QA_PIXEL и берёт медиану
   по всем чистым наблюдениям. Отражение TM/ETM+ приводится к шкале OLI (Roy et al., 2016), чтобы смена
   спутника в 2013 г. не выглядела как изменение. Композиты кэшируются (`composites/Composite_ГОД.tif`).
2. **Метки без ручной работы.** Обучающие пиксели застройки – там, где GHSL BUILT-S (≥ 5 %) подтверждён хотя
   бы одним независимым продуктом того же времени (WSF evolution, WSF 2019, ESA WorldCover, здания OSM).
   Фон – где все продукты молчат с запасом в 5 лет; он делится по спектру на растительность, воду и открытый грунт.
3. **Random Forest на 4 класса:** растительность, застройка, открытый грунт (пески, карьеры, пляжи, пустыри,
   отвалы), вода. Признаки – каналы и индексы года, текстура окрестности и устойчивость пикселя за весь ряд.
4. **Год появления застройки.** По ряду вероятностей для каждого пикселя подбирается одна ступенька
   «нет → есть» с наименьшей ошибкой; новая застройка признаётся, если её подтверждают ≥ 2 года. Застройка не исчезает.

Результаты: `BuiltYear.tif` (год появления, 0 – нет), `BuiltYear_confidence.tif`, `Prob_built_by_year.tif`,
`BareSoil_persistent.tif/.gpkg`, `Urban_RF_ГОД.gpkg`, `annual_series.csv` (площадь и прирост по годам),
`rf_series_protocol.json` (источники меток, точность out-of-bag, важность признаков).

Точки независимой проверки можно передать параметром – их окрестность 120 м исключается из обучения.

## Самый простой автономный запуск

1. Подготовьте отдельную папку индексов. Для каждого года нужны четыре однополосных файла:

   ```text
   NDBI_2000.tif
   BSI_2000.tif
   NDVI_2000.tif
   MNDWI_max_2000.tif
   NDBI_2025.tif
   BSI_2025.tif
   NDVI_2025.tif
   MNDWI_max_2025.tif
   ```

   Допустимы также `MNDWI_ГОД`, расширения `.tiff` и `.vrt`, вложенные папки, любой регистр. Повторяющиеся имена одного индекса/года считаются ошибкой. Если один из найденных годов неполный, запуск останавливается до обработки. Поле «Годы» позволяет выбрать подмножество.

2. Откройте **Модули → Городской анализ → Автономный анализ папки индексов** (также доступно в Processing → Urban Analysis).
3. Укажите папку индексов и родительскую папку результатов. Для анализа конкретного города рекомендуется указать полигон ROI.
4. Нажмите «Выполнить». Расстановка точек и предварительная загрузка растров в проект не нужны.

Модуль найдёт годы, создаст отдельную папку `run_...`, приведёт данные к сетке первого NDBI, ограничит их ROI, исключит общие NoData, рассчитает пороги Оцу + K-Means, выполнит классификацию и сохранит результаты. Если ROI не задан, используется **охват первого NDBI**, а не административная граница города. Лимит – 16 млн пикселей ROI по умолчанию; большие задачи нужно делить или осознанно повышать лимит.

## Что требуется подготовить заранее

- Индексы должны быть корректно рассчитаны и иметь значения в диапазоне [-1, 1], а не целые числа с коэффициентом масштаба.
- Облака, облачные тени, снег и дефекты снимков должны быть обозначены **NoData**. Этот выпуск не скачивает снимки, не рассчитывает индексы из каналов и не распознаёт облака самостоятельно.
- Каждый файл должен иметь CRS и геопривязку. Опорный NDBI должен иметь north-up сетку без вращения; остальные растры могут перепроецироваться.
- Разрешение после выравнивания определяется первым NDBI. Интерполяция не создаёт реальной детализации, которой не было в исходном снимке.
- При малом числе валидных значений, однородных индексах или вырожденных кластерах алгоритм сообщает ошибку вместо подстановки произвольного порога.

## Результаты

В новой папке запуска:

- `ГОД/Urban_Auto_ГОД.gpkg` – независимый результат каждого года;
- `ГОД/Valid_ГОД.tif` – общая маска наблюдаемой территории четырёх индексов;
- `ГОД/run_protocol_ГОД.json` – параметры, формула, сведения о подготовке и метрики;
- `Urban_Consistent_ГОД.gpkg` – временно согласованные контуры при нескольких годах;
- `summary.csv` – площади, прирост, основание расчёта и статус подтверждения;
- `status.json` – параметры задания, SHA-256 входных GeoTIFF/результатов, состояния годов и ошибки;
- `auto_roi.geojson` – автоматически выбранный охват, если пользовательский ROI отсутствовал.

CSV использует разделитель `;` и UTF-8 BOM. Согласованные площади вычисляются на **общей наблюдаемой территории всех лет** и могут отличаться от независимых площадей; значение общей площади записано в `status.json`. Отсутствие данных не считается отсутствием застройки. Минимальное пятно в пакетном режиме – 5 га, морфология +200/-200 м (фиксированные стартовые параметры; для настройки используйте алгоритм одного года).

## Временная динамика

Для старых срезов новое пятно проверяется по последующим наблюдениям (по умолчанию k=2). Если будущих срезов меньше k, используется доступное число и выставляется статус `limited_future_support`.

**Последний год нечем подтвердить «вперёд»**, он маркируется `provisional_last`. По умолчанию (`last_mode='backward'`, как в проверенной версии 4.2.1) новое пятно последнего года принимается, если оно видно и в предыдущем срезе – это нижняя оценка. Режим `accept` принимает последний срез как есть – верхняя оценка. В текстовый отчёт окна пишутся обе оценки. Старое имя `previous` по-прежнему работает как синоним `backward`.

Согласованный ряд предполагает сохранение однажды принятой застройки. Он не подходит для доказательства отсутствия сноса. Для исследований сноса используйте независимые результаты и отдельную разметку изменений.

## Ручной режим

Старое окно «Авто-калибровка застройки» сохранено. Оцу включён по умолчанию; для опорных точек или ручных боксов отключите Оцу. Растры выравниваются и пороги считаются внутри ROI. В 4.3 обрезка по ROI обязательна; прежнее `clip_to_roi=False` отклоняется, чтобы площадь и калибровка относились к одному охвату. В Processing алгоритма одного года доступны пользовательский полигон, строгая проверка сетки и лимит пикселей.

OSM по умолчанию **не заменяется кругом при сетевой ошибке**. В Python API резервный круг включается явно через `allow_osm_fallback=True`; выбранный источник ROI сохраняется в протоколе.

## Возобновление

В автономном алгоритме укажите прежнюю папку `run_...` в поле возобновления и те же входы/параметры. Уже выполненные годы используются повторно только после проверки SHA-256 входных файлов и трёх результатов года. Изменённые исходники или параметры требуют нового запуска. Повреждённые результаты сохраняются как `.previous_...`, после чего год пересчитывается. Для VRT возобновление запрещено: нужно преобразовать индексы в самостоятельные GeoTIFF.

Одновременная запись в одну папку запуска блокируется файлом `.running`. После аварийного завершения проверьте отсутствие работающего процесса перед ручным удалением этого файла. Новые задания всегда получают отдельные папки. При ошибках статус – `failed`, `partial` или `cancelled`, а не «успешно». При `KEEP_GOING` другие годы обрабатываются, но согласование неполного ряда не выполняется.

## Python API (консоль QGIS)

```python
from urban_auto_exp54.urban_auto_batch import run_folder
result = run_folder(r'C:\GIS\indices', r'C:\GIS\results')
print(result['run_dir'], result['status'])
```

С конкретным охватом:

```python
result = run_folder(
    r'C:\GIS\indices', r'C:\GIS\results',
    years=[2000, 2010, 2025],
    roi_path=r'C:\GIS\roi.geojson',
)
```

Вместо полигона можно задать `center=(64.789, 60.125), radius_km=8`. Порядок координат – долгота, широта. Один процесс обработки на задание; один общий экземпляр QGIS нельзя считать потокобезопасным веб-сервисом.

Для получения метрик отдельного вызова ядра используйте `metrics_sink={}` в `run_urban_analysis_core(...)`. Глобальное `run_urban_analysis_core.last_metrics` удалено, чтобы задания не перезаписывали состояние друг друга. Возвращаемая пара `(путь, площадь)` сохранена.

## Командная строка

Запускать Python **из среды QGIS / OSGeo4W**, из каталога, содержащего папку `urban_auto_exp54`, или после добавления родительской папки в PYTHONPATH:

```bash
python -m urban_auto_exp54 --input indices --output results --roi roi.geojson
```

Доступны `--years 2000,2010,2025`, `--strict-grid`, `--max-pixels 16000000`, `--no-temporal`, `--keep-going`, `--resume results/run_...`, `--center 64.789 60.125 --radius-km 8`. Логи выводятся в stderr, итоговый JSON – в stdout; частичный результат и ошибка дают ненулевой код выхода. Это основа для отдельного серверного worker, а не готовый публичный веб-сервис.

## Оценка точности

Матрица ошибок, OA, полнота, точность пользователя, κ и F1. Режим зданий оценивает буфер вокруг объектов и дальний фон; промежуточная полоса не оценивается. Буфер фона не может быть меньше буфера застройки; пересекающиеся эталонные классы отклоняются. NoData и NaN не участвуют в оценке. Для оценки только наблюдаемой территории используйте соответствующий `Valid_ГОД.tif` как опорную сетку.

Шахматка сама по себе не доказывает независимость: контрольные клетки должны быть исключены из подбора точек и параметров заранее. Показатели старой версии по Ураю нельзя автоматически приписывать 4.3.0. Требуется повторная независимая валидация на реальных территориях.
